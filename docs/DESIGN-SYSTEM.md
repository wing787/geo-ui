# デザインシステム仕様書

geo-ui リポジトリの正本。全アプリの見た目はこの文書と `tokens.css` に従う。
実装時は「DESIGN-SYSTEM.md の §X に従って」と、この文書を名指しで参照させること。

---

## 0. 一行で言うと

中立ミニマル（スイス的、余白と整列で見せる）を基調に、light / dark 両対応。
UIのブランド色は極力抑え、色はデータ（地図・凡例）に持たせる。
リアルタイム／データ地図アプリは dark を既定、ポートフォリオと読み物は light を既定にする。

---

## 1. トークンの層構造

色は3層で管理する。UI の色は必ず**セマンティック層**（`--surface`, `--text-primary` 等）を参照し、
プリミティブの生 hex を直接触らない。これにより light/dark の切替が1か所で済む。

```
色のプリミティブ  --c-*      生の値。アプリから直接使わない
   ↓ 意味を与える
セマンティック層  --surface / --text-primary / --border / --accent など。UI の色はここだけ使う
   ↓ 必要なら
コンポーネント層  ボタン・凡例など個別部品のトークン（任意）
```

色以外に2種類ある。

- **スケール**（`--text-*`, `--space-*`, `--radius-*`, `--z-*`, `--duration-*` など）: 寸法の値。アプリから直接使ってよい。
- **データ色**（`--data-*` と `palettes`）: 凡例・地図レイヤなどデータ表現にだけ使う。UI の装飾に使わない（§3）。

### テーマの切替

- 既定は light。ルートまたは地図コンテナに `data-theme="dark"` を付けると、その内側が dark になる。
- dark の中で一部を light に戻すときは `data-theme="light"` を付ける。
- weather-viewer など地図アプリは dark、ポートフォリオは何も付けない（light のまま）。
- 色は CSS の `light-dark()` で定義し、`color-scheme` で切り替える。
  フォーム部品やスクロールバーなどブラウザ標準の見た目もテーマに追従する。
  対応ブラウザは Chrome 123 / Firefox 120 / Safari 17.5 以降。経緯は `docs/adr/0002-light-dark.md`。
- JavaScript からセマンティック色の実値が要るとき、`getPropertyValue("--accent")` は `light-dark(...)` の文字列を返す。
  要素に `color: var(--accent)` を当て、`getComputedStyle(el).color` を読むこと。

`tokens.css` は変数の定義だけを持ち、要素にスタイルを当てない。
`body` とフォーカスリングの既定スタイルは `base.css` に分けてあり、読み込むかはアプリ側が決める。

### 検証

`npm run check` が次を検証する。色を変えたら必ず実行する（CI でも走る）。

- セマンティック層に生の hex が無いこと
- §2 と §3 のコントラスト基準を light / dark の両方で満たすこと
- `tokens.css` の `--data-*` と `src/palettes.ts` の値が一致すること

## 2. カラー（セマンティック）

具体の hex は `tokens.css` を正本とする。ここでは役割と意図を定義。
**トークン名は light / dark で共通**。テーマごとに別名を作らない。

| トークン | 役割 | Light（ポートフォリオ・共通シェル） | Dark（地図アプリの中身） |
|---|---|---|---|
| `--page` | ページ・地図の背景 | わずかに暖かい紙白（#faf9f6）。Anthropic的なクリーム#F4F1EAは避ける | 近黒（#0d1117） |
| `--surface` | カード・パネル面 | 純白 | #161b22 |
| `--surface-2` | surface と区別したい二次面（ホバー、コードブロック、入れ子のパネル） | 一段暗い（#f3f2ec） | 一段明るい（#21262d） |
| `--text-primary` | 本文 | 暖かいチャコール（#1a1a17） | #e6edf3 |
| `--text-secondary` | 補助 | 濃いめのグレー（#52514b） | #a9b1ba |
| `--text-muted` | 注記・プレースホルダ・メタデータラベル | ミュートグレー（#6e6c64） | #8b949e |
| `--border` | 装飾の境界（カード・区切り） | ヘアライン（#e6e4dd） | #262c36 |
| `--border-strong` | 強調境界（ホバー等） | #cfcdc4 | #363c46 |
| `--border-control` | 入力欄など、枠が唯一の手がかりになる部品の境界 | #8a887e | #6e7681 |
| `--divider` | 面の中の区切り線 | #ecebe4 | `--border` と同じ |
| `--accent` | 差し色（リンク、凡例強調、スライダー等） | 抑えたスレート（#2f4858） | ティール（#2dd4bf） |
| `--accent-text` | accent 塗りの上に載る文字 | 白 | 近黒 |
| `--focus-ring` | キーボードフォーカスの輪郭 | `--accent` と同じ | `--accent` と同じ |
| `--status-error` | エラーの文字・アイコン・枠 | #b3261e | #ff7b72 |
| `--status-warning` | 警告の文字・アイコン・枠 | #8a5a00 | #e3b341 |
| `--status-success` | 成功の文字・アイコン・枠 | #1f6f43 | #56d364 |
| `--map-overlay-surface` | 地図の上に浮く面（凡例・パネル・ポップアップ） | `--surface` と同じ | `--surface` と同じ |
| `--map-overlay-border` | 上記の枠。太さは `--map-overlay-border-width`（常に 1px） | `--border-strong` と同じ | `--border-strong` と同じ |
| `--border-width` | 境界の太さ（§5） | 0.5px | 1px |

**アクセントは1画面に1つ**。多用すると意味を失う。色はUIではなくデータに使う、が原則。
フォーカスリングは状態の表示なので、この数に含めない。

### 状態色

- **色だけで状態を伝えない**。必ずアイコンか文言を添える。
  赤と琥珀、赤と緑は、色覚特性によってはほぼ同じ色に見える（シミュレーションで確認済み）。
- 状態色をデータの分類色として使い回さない。データには §3 のパレットを使う。

### 地図の上に浮く面

- 影を使わないので、**不透明な面 + 1px の枠**で地図から切り離す。半透明にしない
  （下の地図の色で文字のコントラストが変わり、基準を保証できなくなる）。
- light でも枠は 1px。0.5px のヘアラインは地図の上では消える。

### コントラストの基準

- `--text-primary` / `--text-secondary` / `--text-muted` / `--accent` / `--status-*` は、
  `--page` / `--surface` / `--surface-2` のどの面に載せても **4.5:1 以上**（WCAG AA）。
  「淡く添える」ラベルもこの下限は守る。
- `--border-control` と `--focus-ring` は同じ3面に対して **3:1 以上**。
- `--border` / `--border-strong` / `--divider` は装飾なので基準なし。枠が見えないと操作できない部品には使わない。
- `npm run check` で検証する（§1）。

## 3. データ可視化パレット（妥協しない）

UIのブランド色とは**別枠**。正本は `src/palettes.ts`（`@wing787/geo-ui/palettes`）で、
`tokens.css` の `--data-*` は同じ値の写し。

**地図レイヤの色は必ず `palettes` から渡す**。MapLibre の paint は WebGL 側で評価され、CSS 変数を読めない。
凡例も同じ配列から作り、地図と凡例の色を二重に定義しない。`--data-*` は CSS だけで色を当てたい場面用。

`light` / `dark` は**地図の背景（ベースマップ）の明るさ**を指す。

### 連続値（sequential）

viridis。降水強度・標高・密度など。虹色（jet）は使わない。

| 名前 | 中身 | 使う場面 |
|---|---|---|
| `sequential.full` | 9停止の全域 | 面の塗りで、端の値が背景に溶けてよいとき（例: 降水なし＝見えなくてよい） |
| `sequential.dark` | 低い側を切った6停止 | 暗い地図の上の線・点、または低い値も読ませたいとき |
| `sequential.light` | 高い側を切った5停止 | 明るい地図の上の線・点、または高い値も読ませたいとき |

- viridis の暗い端（#440154）は暗い背景に対して 1.2:1、明るい端（#fde725）は明るい背景に対して 1.2:1 しかない。
  `dark` / `light` は、背景に対して全停止が 3:1 以上になる範囲だけを残している。
- 凡例には、地図で実際に使った範囲（`full` か切ったものか）をそのまま描く。
- 停止の間は線形補間でよい（9停止あれば本来の viridis とのずれは小さい）。`colorStops()` で値に割り当てる。
- 凡例の色帯は連続的な色の変化になるが、これはデータ表現であり、§5 の「グラデーション禁止」（装飾）には当たらない。

### カテゴリ（categorical）

レイヤ種別・分類など。背景ごとに**5色**。

| | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|
| `categorical.light` | #0072b2 | #d55e00 | #009e73 | #332288 | #882255 |
| `categorical.dark` | #56b4e9 | #e69f00 | #009e73 | #f0e442 | #d55e00 |

- Okabe-Ito を基本に、明るい背景で 3:1 に届かない色を Paul Tol の muted から2色補った。
- どちらの組も、**全ての2色の組み合わせ**が色覚シミュレーション（1型・2型・3型）下で区別でき、
  背景に対して 3:1 以上あることを確認している（2026-11、OKLab の色差で検証）。
- **6分類以上は色を足さない**。分類をまとめるか、形・線種・ラベルを併用する。
  色を足すと、どこかの組み合わせが色覚シミュレーション下で区別できなくなる。
- 色は分類に固定で割り当てる（順位や表示順で塗り替えない）。フィルタで分類が減っても、残った分類の色は変えない。
- 中立のグレーは分類色に使わない（緑や青と区別できなくなる組み合わせがある）。
- 以前の ColorBrewer Dark2 の6色は、ピンクと緑が2型色覚でほぼ同じ色になるため廃止した。

### 発散（diverging）

平年差・増減など、中心からの偏差を表すとき。`[負, 中点, 正]`。

| | 負 | 中点 | 正 |
|---|---|---|---|
| `diverging.light` | #2166ac | #f7f7f7 | #b2182b |
| `diverging.dark` | #67a9cf | #30363d | #ef8a62 |

- 青と赤の対（ColorBrewer RdBu 系）。
- **中点は「偏差なし」なので、背景に沈む色**にする。明るい背景では白に近く、暗い背景では暗いグレー。
  暗い背景で中点を白にすると、「変化なし」が最も目立ってしまう。
- 両端は背景に対して 3:1 以上。

### 凡例

凡例には必ず単位とレンジを添える（例: 「降水強度 mm/h」「0 — 80+」）。
凡例コンポーネントは全アプリ共通の作法（§7）に従う。

## 4. タイポグラフィ

**IBM Plex スーパーファミリーで統一**する（Sans / Mono / Serif が同一設計で揃う）。
理由: 決定を減らせる（restraint）、モノがデータ・座標ラベルと native に噛み合う、
「趣味の良いエンジニア」の温度に合う。Inter などの汎用サンスはあえて避ける（テンプレ感の回避）。

| 役割 | フォント | 用途 |
|---|---|---|
| UI / 本文 | IBM Plex Sans | 画面全般 |
| データ / ラベル | IBM Plex Mono | 座標・数値・メタデータ・小見出しラベル・タグ |
| 声（任意） | IBM Plex Serif | プロジェクト詳細の読み物・引用の一箇所だけ |
| 和文 | IBM Plex Sans JP | 上の3つすべての和文部分 |

- 和文は IBM Plex Sans JP に落とす。`--font-sans` / `--font-mono` / `--font-serif` のどれも、欧文の次に Plex Sans JP を指定している。
  Mono や Serif の中に和文が混じると、その部分は Sans JP になる。
- Serif は欧文の読み物用。和文の長文には使わない（対応する和文セリフ体を持たない）。
- ディスプレイ面にもっと個性が欲しくなったら Sans だけ差し替える余地を残す。

### フォントの配信

- **自前で配信する**。Google Fonts の CDN を直接読み込まない
  （訪問者の IP が第三者に送られ、CSP で外部ドメインを許可する必要が出る）。
- 各アプリが Fontsource のパッケージ（`@fontsource/ibm-plex-sans`、`@fontsource/ibm-plex-sans-jp`、
  `@fontsource/ibm-plex-mono`、必要なら `@fontsource/ibm-plex-serif`）を入れて読み込む。このリポジトリはフォントを同梱しない。
- 読み込むウェイトは 400 と 500 だけ。
- 和文フォントはファイルが大きい。分割配信（unicode-range）が効いているかを、最初のアプリで転送量を見て確認する。

### タイプスケール / ウェイト

- サイズ: 12 / 13 / 14 / 16（本文）/ 18 / 22。12px 未満は使わない。
- ウェイトは **400 と 500 の2つだけ**。600/700 は使わない（重く見える）。
- **常にセンテンスケース**。Title Case も ALL CAPS も使わない（SVG内ラベルや見出しも同様）。
- 行間は本文 1.6〜1.7。

## 5. スペーシング / 形状 / 重なり / 動き

- スペーシングは 4px 基準: 4 / 8 / 12 / 16 / 24 / 32 / 48。縦リズムは rem、部品内の隙間は px。
- 角丸: コントロール 8px、カード 12px、チップ・凡例など小物 4px。
- 片側だけの境界（`border-left` 等のアクセント）には角丸を付けない（0にする）。
- ボーダー: light は 0.5px ヘアライン、dark は 1px（`--border-width`）。
  入力欄など枠で存在を示す部品は `--border-control` を使う（§2）。
- **影・グラデーション・グロー・ネオンは使わない**。フラットに保つ。
- フォーカスリング: `--focus-ring` の色で 2px、要素から 2px 離す（`--focus-ring-width` / `--focus-ring-offset`）。
  `:focus-visible` にだけ出す。`base.css` に既定の実装がある。

### 重なり順

`z-index` に数値を直接書かず、次のトークンを使う。

| トークン | 値 | 対象 |
|---|---|---|
| `--z-base` | 0 | 通常のコンテンツ、地図本体 |
| `--z-map-control` | 10 | 地図上のボタン・凡例・スケール表示 |
| `--z-panel` | 20 | サイドパネル・ドロワー |
| `--z-popup` | 30 | ポップアップ・ツールチップ・メニュー |
| `--z-modal` | 40 | モーダル |
| `--z-toast` | 50 | 通知 |

地図コンテナには `isolation: isolate` を付け、地図ライブラリが内部で使う `z-index` を外に漏らさない。

### 動き

- 時間は `--duration-fast`（120ms。ホバー・押下）と `--duration-base`（200ms。開閉・切替）の2つ。
  イージングは `--ease-standard`。
- `prefers-reduced-motion: reduce` のとき、両方の時間は 0ms になる（`tokens.css` が切り替える）。
  アニメーションは必ずこのトークンで時間を指定し、個別に対応を書かなくて済むようにする。
- 動かすのは状態の変化を伝えるときだけ。装飾のためのアニメーションはしない。

## 6. 汎用コンポーネント（骨子）

shadcn/ui を土台に、上記トークンで着色する。個別の詳細実装はコード側で詰めるが、原則:

- **ボタン**: 既定は控えめ（透明背景 + 細ボーダー）。塗りつぶしの primary は1画面に1つまで。
- **カード**: 白面 + 0.5px ボーダー + 12px 角丸。ポートフォリオの作品カードはこれ。
- **タグ / チップ**: モノ、小さく、細ボーダー。スタック表記（例: `MapLibre · PMTiles`）に使う。
- コピーはセンテンスケース、能動態。ボタンは動詞始まり（「地点を検索」「レイヤを表示」）。
- 空状態・エラーは方向を示す（何が起きたか + どうするか）。UIの声で書く。謝らない。

## 7. 地図UIコンポーネント（地理空間アプリ共通の作法）

普通のWebアプリにない、地図アプリ横断で必要な部品。**最初からデザインシステムに定義**しておく。
これらが揃って一貫していることが「地理空間を分かっている」印象の核になる。

- **レイヤトグル**: オン/オフを色の濃淡で明示。オフは薄いテキスト + 空のスウォッチ。
- **凡例（legend）**: §3のデータパレットを使い、単位とレンジを併記。sequential / categorical / diverging の3型。
- **タイムスライダー**: 時系列データ（ナウキャスト等）前提で用意。再生ボタン + トラック + ハンドル + 時刻表示。
- **フィーチャポップアップ / ツールチップ**: 選択地点の値表示。`--map-overlay-*` の面に載せる（§2）。
- **ベースマップ切替**: 明地図 / 暗地図の切替（アプリのテーマと連動）。
- **座標・スケール表示**: モノで控えめに。位置の信頼感を出す。

### ベースマップとテーマの連動

- ベースマップの明暗は、地図コンテナの `data-theme` に合わせる。UI が dark なら暗い地図、light なら明るい地図。
- ベースマップは、**明・暗の両方のスタイルを持つもの**を選ぶ（例: Protomaps のベースマップ）。
  片方しか無いものを自前で反転させない。
- 切替は `map.setStyle()` で行う。スタイルを差し替えるとアプリが足したソースとレイヤは消えるので、
  `style.load` のあとで足し直す。
- そのために、**アプリのレイヤ定義は「テーマを受け取ってレイヤの配列を返す純粋な関数」として書く**
  （例: `buildLayers(theme)`）。初回表示と切替後の足し直しが同じ関数で済み、地図を起動せずにテストできる。
- レイヤの色は `palettes` の `light` / `dark` をテーマで選ぶ。CSS 変数は地図レイヤからは読めない（§3）。
- 選択中のフィーチャの強調など、地図レイヤに UI の色（`--accent`）が要るときは、§1 の方法で実値を読んで渡す。
- 凡例は地図と同じテーマ・同じ配列から描く。テーマを切り替えたら凡例も描き直す。

## 8. シグネチャ（この作品群を記憶させる一点）

**モノのメタデータラベル + 一貫したデータ凡例**を、全アプリに反復して現れる共通モチーフにする。
座標・単位・時刻・出典を IBM Plex Mono で淡く添え、凡例は常に同じ作法で置く。
派手さはここに集約し、それ以外は静かに保つ。地理空間データ由来の「素材の手触り」を、この反復で出す。

## 9. 品質フロア（言わずに満たす）

- モバイルまでレスポンシブ。
- キーボードフォーカスが見える（§5 のフォーカスリング）。
- `prefers-reduced-motion` を尊重（§5 のトークンを使えば満たせる。過剰な動きはAI生成臭を生む）。
- light / dark の両方で、§2 のコントラスト基準（文字 4.5:1、コントロールの枠 3:1）を満たす。
- 状態と分類を色だけで伝えない（§2 状態色、§3 カテゴリ）。
