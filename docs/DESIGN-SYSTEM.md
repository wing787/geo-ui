# デザインシステム仕様書

geo-ui リポジトリの正本。全アプリの見た目はこの文書と `tokens.css` に従う。
実装時は「DESIGN-SYSTEM.md の §X に従って」と、この文書を名指しで参照させること。

---

## 0. 一行で言うと

**図葉（ずよう）**。地図を一枚の図として組み、UI は無彩色にして、色はすべてデータに使う。

- 地図は図郭（枠線）で囲み、経緯度の目盛を枠の外に出す。
- 凡例・読み取り値・レイヤ・時刻の操作・縮尺・出典は、地図の上に浮かべず、図郭の外の余白（整飾）に置く。
- UI に差し色を持たない。画面に色が見えたら、それはデータである。
- light / dark の両対応。リアルタイム／データ地図アプリは dark、ポートフォリオと読み物は light を既定にする。

経緯は `docs/adr/0003-map-sheet-direction.md`。

## 1. トークンの層構造

色は3層で管理する。UI の色は必ず**セマンティック層**（`--surface`, `--text-primary` 等）を参照し、
プリミティブの生 hex を直接触らない。これにより light/dark の切替が1か所で済む。

```
色のプリミティブ  --c-*      生の値。アプリから直接使わない
   ↓ 意味を与える
セマンティック層  --surface / --text-primary / --border / --map-land など。UI の色はここだけ使う
   ↓ 必要なら
コンポーネント層  ボタン・凡例など個別部品のトークン（任意）
```

色以外に2種類ある。

- **スケール**（`--text-*`, `--space-*`, `--radius-*`, `--z-*`, `--duration-*` など）: 寸法の値。アプリから直接使ってよい。
- **データ色**（`--data-*` と `palettes`）: 凡例・地図レイヤなどデータ表現にだけ使う。UI の装飾に使わない（§3）。

### テーマの切替

- 既定は light。ルートまたは地図コンテナに `data-theme="dark"` を付けると、その内側が dark になる。
- dark の中で一部を light に戻すときは `data-theme="light"` を付ける。
- 色は CSS の `light-dark()` で定義し、`color-scheme` で切り替える。
  フォーム部品やスクロールバーなどブラウザ標準の見た目もテーマに追従する。
  対応ブラウザは Chrome 123 / Firefox 120 / Safari 17.5 以降。経緯は `docs/adr/0002-light-dark.md`。
- **`data-theme` を付けた要素には、地の色と文字の色を必ず当て直す**
  （`background-color: var(--page); color: var(--text-primary);`。`base.css` がこれを行う）。
  `color` は、light / dark のどちらかに確定した値で子孫に継承される。当て直さないと、dark の領域の中に light の文字色が残る。
  `accent-color` など、継承される色のプロパティも同じ。地の色を持たない要素に `data-theme` を付けない。
- セマンティック層のトークンを `@property` で `<color>` として登録しない（登録すると、同じ理由でテーマの入れ子が効かなくなる）。
- 各アプリの HTML には `<meta name="color-scheme" content="light">`（dark のアプリは `dark`）を入れる。
  CSS が届く前の最初の描画で、背景が逆の色で一瞬出るのを減らせる。
- JavaScript からセマンティック色の実値が要るとき、`getPropertyValue("--map-land")` は `light-dark(...)` の文字列を返す。
  要素に `color: var(--map-land)` を当て、`getComputedStyle(el).color` を読むこと。

`tokens.css` は変数の定義だけを持ち、要素にスタイルを当てない。
`body` とフォーカスリングの既定スタイルは `base.css` に分けてあり、読み込むかはアプリ側が決める。

### 検証

`npm run check` が次を検証する。色を変えたら必ず実行する（CI でも走る）。

- セマンティック層に生の hex が無いこと
- UI の色のプリミティブ（状態色を除く）が無彩色であること
- §2 のコントラスト基準を light / dark の両方で満たすこと
- `tokens.css` の `--data-*` と `src/palettes.ts` の値が一致すること
- 連続の配色が、小さい値を背景に近い側にする向きになっていること（§3）

### 差し色を持たない理由

- 地図アプリでは、画面の色のほとんどをデータが占める。UI に色があると、データの色と競合する。
  検討した差し色（マゼンタ、ティール）は、色覚シミュレーション下でデータの色と区別できなかった。
- 強調は、インク（`--text-primary`）の塗り・太さ・位置で行う。押されたボタンはインクで塗り、文字を `--page` にする。
- リンクは下線で示す。色を変えない。
- 基図（海・陸・海岸線）も無彩色にする。気象庁の指針も、陸の背景は「灰色の濃淡が望ましい」としている。

### 状態色

- UI で色を持つのは状態（エラー・警告・成功）だけ。
- **色だけで状態を伝えない**。必ずアイコンか文言を添える。
  赤と琥珀、赤と緑は、色覚特性によってはほぼ同じ色に見える（シミュレーションで確認済み）。
- 状態色をデータの分類色として使い回さない。データには §3 の配色を使う。

### 地図の上に浮く面

- 原則として浮かべない。凡例や読み取り値は図郭の外に置く（§7）。
- 画面が狭いなどの理由で浮かべるときは、**不透明な面 + 1px の枠**で地図から切り離す。半透明にしない
  （下の地図の色で文字のコントラストが変わり、基準を保証できなくなる）。
- 影ではコントラストを確保できない。枠は `--border-control`（3:1 以上）を使う。

### コントラストの基準

- `--text-primary` / `--text-secondary` / `--text-muted` / `--status-*` は、
  `--page` / `--surface` / `--surface-2` のどの面に載せても **4.5:1 以上**（WCAG AA）。
  大きい文字にも 3:1 の緩和を使わない。
- `--border-control` と `--focus-ring` は同じ3面に対して **3:1 以上**。
- `--border` / `--border-strong` / `--divider` は装飾なので基準なし。枠が見えないと操作できない部品には使わない。
- `npm run check` で検証する（§1）。

## 3. データの配色（妥協しない）

正本は `src/palettes.ts`（`@wing787/geo-ui/palettes`）で、`tokens.css` の `--data-*` は一部の値の写し。

**地図レイヤの色は必ず `palettes` から渡す**。MapLibre の paint は WebGL 側で評価され、CSS 変数を読めない。
凡例も同じ配列から作り、地図と凡例の色を二重に定義しない。`--data-*` は CSS だけで色を当てたい場面用。

`light` / `dark` は**地図の背景（基図）の明るさ**を指す。

### データの種類と配色の対応

配色は、データの種類ごとに決める。経緯は `docs/adr/0004-colormaps-by-data-type.md`。

| データ | 配色 | `palettes` の名前 | テーマで変わるか |
|---|---|---|---|
| 降水強度 | 気象庁の降水ナウキャスト（8階級） | `convention.jmaRain` | 階級が変わる（下記） |
| 気温 | 気象庁の指針（10階級） | `convention.jmaTemperature` | 変わらない |
| 気象の平年比（気温） | 気象庁の季節予報（11階級） | `convention.jmaAnomalyTemperature` | 変わらない |
| 気象の平年比（降水量） | 気象庁の季節予報（11階級） | `convention.jmaAnomalyPrecipitation` | 変わらない |
| 標高 | Hypsometric Tint | `convention.hypsometric` | 変わらない |
| 光学の衛星画像 | 配色なし（バンドの割り当てを示す） | — | — |
| SAR などの強度画像 | grayC | `image.grayC` | 変わらない |
| 件数・密度など、慣例のない連続値 | viridis | `sequential` | 向きが変わる |
| 一般の増減（前年比など） | RdYlBu（11階級） | `diverging` | 変わらない |
| 種別・分類 | 検証済みの5色 | `categorical` | 色の組が変わる |

表にない種類を扱うときは、先にこの表に行を足す。

### ラスターは2種類に分ける

- **画像として読むもの**（光学、SAR）: 配色を当てないか、無彩色の濃淡（`image.grayC`）にする。
  **テーマが変わっても向きを変えない**。SAR で水域が明るくなると読めなくなる。
  光学画像の凡例は色帯ではなく、バンドの割り当て（例: 「R: B4、G: B3、B: B2」）を示す。
- **値として読むもの**（標高、指数、降水、件数）: 上の表の配色を当てる。

### 慣例の配色（convention）

値と色の対応が社会的に決まっているもの。見る人がすでに覚えている色を優先する。

- **色と階級の境界を変えない**。補間したり、テーマに合わせて向きを変えたりしない。
- **凡例の近くに出典を表示する**（下の「出典と表示」）。
- 気象庁の配色は虹色に近い並びだが、慣例として例外にする。これ以外で虹色の配色を既定にしない。

降水（`convention.jmaRain`、mm/h）:

| 階級 | 0〜1 | 1〜5 | 5〜10 | 10〜20 | 20〜30 | 30〜50 | 50〜80 | 80 以上 |
|---|---|---|---|---|---|---|---|---|
| 色 | #f2f2ff | #a0d2ff | #218cff | #0041ff | #fff500 | #ff9900 | #ff2800 | #b40068 |

- **暗い背景では、最初の階級（1 mm/h 未満）を描かない**。ほぼ白なので、暗い地の上では最も弱い雨が最も目立ってしまう。
  `jmaRainFor(theme)` がこの切り替えを行う。凡例にも、描いた階級だけを載せる。
- 暗い背景では 80 以上の紫（#b40068）のコントラストが低い（約 2.4:1）。縁取り（§7）で補う。

気温（`convention.jmaTemperature`、℃）は −5 / 0 / 5 / 10 / 15 / 20 / 25 / 30 / 35 を境界とする10階級。
平年比の2つは11色の並びだけを持つ。階級の境界は資料ごとに違うので、アプリ側で決める。
中央の階級がほぼ白なので、暗い背景では「平年並み」が最も明るく見える。使うときは明るい背景を勧める。

標高（`convention.hypsometric`）は、低地の緑 → 褐色 → 山頂の白の11停止。停止の間は補間してよい。
陸の標高にだけ使う。水深には使わない。

### 連続値（sequential）

件数・密度など、慣例の配色を持たない連続値。viridis（matplotlib の値）。

| 名前 | 中身 |
|---|---|
| `sequential.full` | 9停止の全域。暗 → 明の順 |
| `sequential.dark` | 暗い背景用。小さい値が暗い側。背景に沈む端を1停止切ってある |
| `sequential.light` | 明るい背景用。小さい値が明るい側（`full` の逆順）。背景に沈む端を1停止切ってある |

- **小さい値を背景に近い側にする**。「少ない＝目立たない、多い＝目立つ」が、どちらのテーマでも成り立つ。
- 凡例には、地図で実際に使った範囲をそのまま描く。
- 停止の間は線形補間でよい。`colorStops()` で値に割り当てる。
- 凡例の色帯は連続的な色の変化になるが、これはデータ表現であり、§5 の「グラデーション禁止」（装飾）には当たらない。
- 明るい背景では viridis の黄緑が強く出る。気になる場面が増えたら、明るい背景用の配色を別に選ぶ（ADR 0004 の見直し条件）。

### 発散（diverging）

前年比・増減など、中心からの偏差。RdYlBu の11階級（ColorBrewer）。`[減少 … 増加]` の順で、減少が青、増加が赤。

`#313695 #4575b4 #74add1 #abd9e9 #e0f3f8 #ffffbf #fee090 #fdae61 #f46d43 #d73027 #a50026`

- 明るい背景・暗い背景とも同じ配色を使う。
- 中央（#ffffbf）は淡い黄色。暗い背景では「変化なし」が最も明るく見える。これは承知のうえで選んでいる（ADR 0004）。
- 気象の平年比には、この配色ではなく気象庁の配色を使う。

### カテゴリ（categorical）

レイヤ種別・分類など。背景ごとに**5色**。

| | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|
| `categorical.light` | #0072b2 | #d55e00 | #009e73 | #332288 | #882255 |
| `categorical.dark` | #56b4e9 | #e69f00 | #009e73 | #f0e442 | #d55e00 |

- Okabe-Ito を基本に、明るい背景で 3:1 に届かない色を Paul Tol の muted から2色補った。
- どちらの組も、**全ての2色の組み合わせ**が色覚シミュレーション（1型・2型・3型）下で区別でき、
  ページと地図の陸（`--page` / `--map-land`）に対して 3:1 以上あることを確認している（2026-11、OKLab の色差で検証）。
- 明るい背景の水域（`--map-water`）の上では、緑（#009e73）が 2.7:1 で 3:1 に届かない。縁取り（§7）で補う。
- **6分類以上は色を足さない**。分類をまとめるか、形・線種・ラベルを併用する。
- 色は分類に固定で割り当てる（順位や表示順で塗り替えない）。フィルタで分類が減っても、残った分類の色は変えない。
- 中立のグレーは分類色に使わない。
- 線は、色に加えて太さでも種別を分ける。

### 既定にしない配色（optional）

`optional.turbo`（matplotlib の turbo）を選べるようにしてある。**既定にしない。値の大小を読ませる図には使わない。**

- 虹色の配色で、明るさが値の順に並ばない（中間が最も明るく、両端が暗い）。
  白黒や色覚の特性によっては、多い少ないの順序が読めなくなる。
- 小さい値が背景に沈まないので、「データがほとんどない場所」が画面で最も強い色になる。
- 使ってよいのは、画像の細かい差を目立たせたい場面など、順序の正確さより差の見えやすさを優先するとき。
  使うときは、凡例に数値を必ず添える。

### データなし

- 欠測（雲、観測範囲外など）には色を割り当てない。地の色のままにする。
- 凡例に「データなし」を載せる。

### 凡例

凡例には必ず単位とレンジを添える（例: 「降水強度 mm/h」）。階級のある配色は、階級ごとに境界の値を書く。
凡例は全アプリ共通の作法（§7）に従う。

### 出典と表示

| 配色 | 出典 | 条件 |
|---|---|---|
| 気象庁の配色 | 気象庁ホームページ「気象情報の配色に関する設定指針」、降水ナウキャストの凡例 | 公共データ利用規約（第1.0版）。「出典：気象庁ホームページ」と表示する |
| viridis、turbo | matplotlib（turbo の原典は Google、Apache 2.0） | 表示は任意 |
| RdYlBu | ColorBrewer（Cynthia Brewer ほか） | Apache 2.0 |
| grayC | Scientific colour maps（Fabio Crameri） | MIT。論文での引用が推奨されている |
| Hypsometric Tint | GeoPalettes（Dominic Royé） | CC BY 4.0。表示が必要 |
| カテゴリ色 | Okabe-Ito、Paul Tol | 表示は任意 |

表示が必要なもの（気象庁、GeoPalettes）は、その配色を使った地図の出典欄に書く。
ライセンスの条件は、採用時に各配布元の記載を読んだ範囲のもの。公開前に配布元で確認し直す。

## 4. タイポグラフィ

**IBM Plex で統一**する。

| 役割 | トークン | フォント | 用途 |
|---|---|---|---|
| UI / 本文 | `--font-sans` | IBM Plex Sans | 画面全般 |
| 整飾のデータ | `--font-data` | IBM Plex Sans Condensed | 目盛、凡例の数値、読み取り値、縮尺、出典。数字は等幅（`font-variant-numeric: tabular-nums`） |
| コード | `--font-mono` | IBM Plex Mono | コードだけ |
| 和文 | — | IBM Plex Sans JP | 上の3つすべての和文部分 |

- 小さいデータのラベルに等幅フォントを使わない（生成されたページによくある見た目になる）。
  桁を揃えたいときは、Condensed の等幅数字を使う。
- 和文に斜体を使わない。
- 字間は `--tracking-body`（0.02em）。和文の本文の読みやすさのため。

### フォントの配信

- **自前で配信する**。Google Fonts の CDN を直接読み込まない
  （訪問者の IP が第三者に送られ、CSP で外部ドメインを許可する必要が出る）。
- 各アプリが Fontsource のパッケージ（`@fontsource/ibm-plex-sans`、`@fontsource/ibm-plex-sans-condensed`、
  `@fontsource/ibm-plex-sans-jp`、必要なら `@fontsource/ibm-plex-mono`）を入れて読み込む。このリポジトリはフォントを同梱しない。
- 読み込むウェイトは 400 と 500 だけ。
- 和文フォントはファイルが大きい。分割配信（unicode-range）が効いているかを、最初のアプリで転送量を見て確認する。

### タイプスケール / ウェイト

| トークン | 大きさ | 用途 |
|---|---|---|
| `--text-map` | 12px | **図郭の目盛、縮尺、出典の3つだけ** |
| `--text-sm` | 14px | 凡例、読み取り値、レイヤ、ボタン、補助の文 |
| `--text-base` | 16px | 本文 |
| `--text-lg` | 18px | 小見出し |
| `--text-xl` | 22px | 見出し |

- 読ませる文字と操作する文字は **14px 以上**。12px を認めるのは、地図の一部である上の3つだけ。12px 未満は使わない。
- トークンの値は rem で持つ（表の大きさは、ブラウザの既定の 16px のとき）。利用者がブラウザで設定した文字サイズに追従させるため。
  `:root` / `html` に `font-size` を指定しない。文字サイズを px で直接書かない。
- 文字を含む部品（ボタン、凡例の行など）に固定の高さを指定しない。文字を 200% に拡大しても、切れたり重なったりしないこと。
- ウェイトは **400 と 500 の2つだけ**。
- **常にセンテンスケース**。Title Case も ALL CAPS も使わない。
- 行間は本文 1.6〜1.7。1.5 を下回らない。

## 5. スペーシング / 形状 / 重なり / 動き

- スペーシングは 4px 基準: 4 / 8 / 12 / 16 / 24 / 32 / 48。
- **面は直角**。パネル、カード、地図、凡例の色見本に角丸を付けない。
- 角丸は、ボタン・入力欄などの操作部品にだけ 3px（`--radius-control`）。
- ボーダーは 1px（`--border-width`）。light / dark で変えない。
- **影・グラデーション・グロー・ネオンは使わない**。フラットに保つ。
- フォーカスリング: インク（`--focus-ring`）の 2px の輪郭を要素から 2px 離して描き、
  その外側に地の色（`--focus-ring-halo`）を 2px 重ねる。二重にするのは、どの面の上でも見えるようにするため。
  `:focus-visible` にだけ出す。`base.css` に既定の実装がある。

### 重なり順

`z-index` に数値を直接書かず、次のトークンを使う。

| トークン | 値 | 対象 |
|---|---|---|
| `--z-base` | 0 | 通常のコンテンツ、地図本体 |
| `--z-map-control` | 10 | 地図上のボタン・スケール表示 |
| `--z-panel` | 20 | サイドパネル・ドロワー |
| `--z-popup` | 30 | ポップアップ・ツールチップ・メニュー |
| `--z-modal` | 40 | モーダル |
| `--z-toast` | 50 | 通知 |

地図コンテナには `isolation: isolate` を付け、地図ライブラリが内部で使う `z-index` を外に漏らさない。

### 動き

- 時間は `--duration-fast`（120ms。ホバー・押下）と `--duration-base`（200ms。開閉・切替）の2つ。
  イージングは `--ease-standard`。
- `prefers-reduced-motion: reduce` のとき、両方の時間は 0ms になる（`tokens.css` が切り替える）。
- 動かすのは状態の変化を伝えるときだけ。装飾のためのアニメーションはしない。

## 6. 汎用コンポーネント（骨子）

shadcn/ui を土台に、上記トークンで着色する。個別の詳細実装はコード側で詰めるが、原則:

- **ボタン**: 透明の背景 + `--border-control` の枠 + 3px の角丸。押された状態（選択中）はインクで塗り、文字を `--page` にする。
- **チェックボックス、スライダーなど**: ブラウザ標準の部品（`<input type="checkbox">`、`<input type="range">`）を使い、
  `<div>` で作り直さない。色は `accent-color` をインクにして無彩色に保つ（`base.css`）。オンは色ではなく印で示す。
  Safari は `accent-color` の上の印の色を自動では選び直さないことがあるので、両テーマで Safari の表示を確認する。
- 押せる範囲は 44px 四方以上を確保する（見た目の大きさは小さくてよい。`<label>` で広げる）。
- **パネル / カード**: 直角。面の色の差（`--surface` と `--page`）か 1px の枠で区切る。
- **リンク**: 下線。色は本文と同じ。
- コピーはセンテンスケース、能動態。ボタンは動詞始まり（「地点を検索」「レイヤを表示」）。
  切り替えのボタンは、押すと何が起きるかを書く（「暗い表示にする」）。
- 空状態・エラーは方向を示す（何が起きたか + どうするか）。UIの声で書く。謝らない。
- スイッチ、表、通知などの操作とアクセシビリティの仕様は、デジタル庁デザインシステムを参照する。
  見た目は借りない（下の「参考にしたもの」）。

## 7. 地図UIコンポーネント（図葉の作法）

### 図葉の構成

```
        138°30′E      139°E       139°30′E
       ┌──┴───────────┴────────────┴──────┐   凡例（単位つき）
36°N ──┤                                  │
       │            地図                  │   選択地点の読み取り値
       │                                  │
35°30′─┤                                  │   レイヤ
       └──────────────────────────────────┘
        ├──┼──┤ 50 km      出典             時刻の操作（時系列のとき）
```

- **図郭**: 地図をインクの 1px の線で囲む。角丸なし。
- **目盛**: 経緯度の値を図郭の外に書き、短い刻みを枠に付ける。`--font-data`、12px。
- **整飾**: 凡例、読み取り値、レイヤ、時刻の操作は図郭の外に置く。広い画面では右、狭い画面では下。
  地図の上に面を浮かべない（地図を隠さない。コントラストを保証できる）。
- **縮尺と出典**: 図郭の下。12px。出典には、データと配色の両方を書く（§3「出典と表示」）。

### 部品

- **凡例**: §3 の配色から描く。単位を必ず書く。連続・階級・発散・カテゴリ・画像（バンドの割り当て）の5型。
- **読み取り値**: 選択した地点やフィーチャの値。数値は `--font-data` の等幅数字。
- **レイヤの切替**: チェックボックス。オンはインクの塗り。
- **時刻の操作**: 時系列データ用。再生ボタン + スライダー + 時刻の表示。
- **縮尺**: 線と数値。

### ベクターの描き方

- **点・線・ポリゴンの輪郭は、必ず地の色（`--map-casing`）で縁取る**。
  衛星画像の上に載ると、色だけでは沈む。
- 線は、色に加えて太さでも種別を分ける（§3 カテゴリ）。

### 選択の表し方

差し色がないので、選択は次の3つを重ねて示す。

1. フィーチャを地の色（`--map-casing`）で縁取る。
2. その外側をインク（`--map-selection`）の輪郭で囲む。
3. 図郭の目盛に、選択した位置の経緯度を太字で出す。

データの色は変えない（選択しても値の色は同じ）。

### 基図とテーマの連動

- 基図は無彩色にする（`--map-water` / `--map-land` / `--map-coast`）。色はデータのために空けておく。
- 基図の明暗は、地図コンテナの `data-theme` に合わせる。
- タイルの基図を使うときは、**明・暗の両方のスタイルを持つもの**を選ぶ（例: Protomaps）。片方を自前で反転させない。
  彩色されたスタイルは、無彩色に調整して使う。
- 切替は `map.setStyle()` で行う。スタイルを差し替えるとアプリが足したソースとレイヤは消えるので、
  `style.load` のあとで足し直す。
- そのために、**アプリのレイヤ定義は「テーマを受け取ってレイヤの配列を返す純粋な関数」として書く**
  （例: `buildLayers(theme)`）。初回表示と切替後の足し直しが同じ関数で済み、地図を起動せずにテストできる。
- テーマで変わる配色（`sequential`、`categorical`、`jmaRainFor`）は、テーマを渡して選ぶ。
  画像として読むもの（光学、SAR）と慣例の配色は、テーマで変えない（§3）。
- 地図レイヤに UI の色（`--map-casing`、`--map-selection`）を渡すときは、§1 の方法で実値を読む。
- 凡例は地図と同じテーマ・同じ配列から描く。テーマを切り替えたら凡例も描き直す。

## 8. シグネチャ（この作品群を記憶させる一点）

**図郭と、その外に出た目盛**。どのアプリの地図も同じ枠で囲まれ、経緯度が枠の外に並ぶ。
凡例・縮尺・出典は必ず同じ位置にある。

派手さはデータの色に任せ、それ以外は無彩色で静かに保つ。

---

## 9. 品質フロア（言わずに満たす）

- モバイルまでレスポンシブ。狭い画面では整飾を地図の下に回す。
- キーボードフォーカスが見える（§5 のフォーカスリング）。
- `prefers-reduced-motion` を尊重（§5 のトークンを使えば満たせる）。
- light / dark の両方で、§2 のコントラスト基準（文字 4.5:1、コントロールの枠 3:1）を満たす。
- 状態と分類を色だけで伝えない（§2 状態色、§3 カテゴリ）。
- 地図には必ず、単位つきの凡例、縮尺、出典がある。
- 文字を 200% に拡大しても、幅 320px でも、内容が欠けず横スクロールが出ない（地図本体を除く）。
- 強制カラーモード（Windows のハイコントラスト）では、ブラウザが作者の色を上書きする。
  凡例の色見本は色そのものが情報なので、`forced-color-adjust: none` を付けて色を残す。それ以外の部品には付けない。
  押された状態や選択を背景色だけで示していると消えるので、枠線か印を併用する。
