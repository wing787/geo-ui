# ADR 0004: 配色をデータの種類ごとに決める

- 状態: 採用
- 決定日: 2026-11-16
- 見直しの目安: 下の「見直すタイミング」のどれかに当たったとき

## 背景

v0.2.0 の配色は、型ごとに1つだった（連続は viridis、発散は青と赤の3色、カテゴリは5色）。
扱うデータは、ベクター（ポイント・ライン・ポリゴン）とラスター（衛星画像、SAR、DEM など）で、
降水のように、見る人がすでに色を覚えているデータもある。型ごとに1つでは合わなかった。

確認用のモックに候補を並べ、データの種類ごとに両テーマで見比べて決めた。
候補の出どころは、CARTOColors、matplotlib、Scientific colour maps（Crameri）、GeoPalettes、気象庁の指針。

## 決定

| データ | 配色 | 決めた理由 |
|---|---|---|
| 降水強度 | 気象庁の降水ナウキャスト | 日本の利用者が覚えている色。指定による |
| 気温、気象の平年比 | 気象庁の指針 | 降水と揃える |
| 光学の衛星画像 | 配色なし | 画像そのものを見せる |
| SAR | grayC | 知覚的に均等な無彩色。単純な黒から白より中間の階調が均等 |
| 一般の増減 | RdYlBu（11階級）。両テーマ共通 | 指定による |
| 標高 | Hypsometric Tint | 指定による。地形図の慣例に近い |
| 件数・密度 | viridis | 連想のない中立の既定値。明るさが値の順に並ぶ |
| 種別 | v0.2.0 の5色 | 検証済みのものを維持 |

あわせて、次のルールを決めた。

1. **ラスターを「画像として読むもの」と「値として読むもの」に分ける**。前者はテーマで向きを変えない。
2. **慣例の配色**という区分を作る。色と階級を変えず、テーマで向きを変えず、出典を表示する。
3. **連続の配色は、小さい値を背景に近い側にする**。v0.2.0 の `sequential.light` は逆向きだったので直した。
4. **暗い背景では、気象庁の降水の最初の階級（1 mm/h 未満）を描かない**。
5. **ベクターは必ず地の色で縁取る**。

## 検討の経過

### 降水

当初は CARTO の BluYl を推していた。気象庁の配色は黄色から赤への並びで、虹色に近い。
それでも、見る人が意味を覚えている色を優先した。「虹色を作らない」というルールに、慣例の配色という例外を設けた。

暗い背景では、最初の階級（#f2f2ff）が最も目立つ。弱い雨の縁が白く光る。
この階級だけ描かないことにした。色そのものは変えていない。

### 一般の増減

候補の変遷: RdBu（明）と berlin（暗）→ vik（明）と berlin（暗）→ ThermClassic（両テーマ）→ **RdYlBu（両テーマ）**。

- 最初の2案は、中央の色を背景に沈めるために、明暗で別の配色を使う案だった
  （明るい背景は中央が白、暗い背景は中央が暗い）。
- GeoPalettes の ThermClassic は、値が ColorBrewer の RdBu（11階級）と同じだった。
- 最終的に、両テーマ共通の RdYlBu になった。
  **暗い背景では、中央の淡い黄色（「変化なし」）が最も明るく見える**。これは承知のうえの選択である。
  v0.2.0 の仕様にあった「中点は背景に沈む色にする」というルールは、この決定で廃止した。

### 標高

候補の変遷: BrwnYl（CARTO）→ matplotlib の terrain → **Hypsometric Tint（GeoPalettes）**。

- matplotlib の terrain は下位 25% が海の青で、陸だけの標高に使うと低地が青くなる。
  陸の部分だけを使っても、低地が鮮やかな緑（#00cc66）になり、平野が画面で最も強い色になった。
- Hypsometric Tint は低地の緑が淡い。山頂が白なので、暗い背景では山頂が強く出る。

### 件数・密度と turbo

turbo の指定があり、モックで確認した。

- 件数がほぼない六角形が、鮮やかな青で一面に塗られた。
- 最も明るいのは中間の階級で、最大の階級は暗い赤だった。暗い背景では最大の階級が沈んだ。

turbo は jet の改良版だが、虹色であることは変わらない。3案を比べた。

- A. turbo を既定にし、「虹色禁止」のルールを外す。
- B. 順序が読める配色を既定にし、turbo は入れない。
- **C（採用）. 既定は viridis。turbo は `optional.turbo` として選べるようにし、
  「既定にしない。値の大小を読ませる図には使わない」と仕様に書く。**

ポートフォリオでは配色の選び方そのものが見られる。件数の既定が虹色だと、地図の経験者ほど気になると判断した。

### GeoPalettes の扱い

変数ごとに配色を引ける索引として使った。値の取り方には注意が要る。

- Crameri の配色は 5〜8 色に間引かれ、値も元と少し違う。grayC は配布元のパッケージ（cmcrameri 1.8）から取った。
- 「Teal Cascade」は CARTOColors の Teal と同じ値、「ThermClassic」は ColorBrewer の RdBu と同じ値だった。
  出典は元の作者として扱う。
- Hypsometric Tint は GeoPalettes 独自の配色なので、GeoPalettes の値をそのまま使った。
- 暗い背景についての記述はない。

## この決定で生じること

- **破壊的変更（v0.3.0）**。`diverging` は「テーマごとの3色」から「テーマ共通の11色」になった。
  `sequential.light` / `sequential.dark` は中身と向きが変わった。viridis の値を matplotlib のものに直した（4停止の値がわずかに違っていた）。
  `--data-div-*` と `--data-seq-*` の値が変わった。
- 追加: `convention`、`image`、`optional`、`attribution`、`jmaRainFor()`、`classIndex()`、`stepArgs()`。
- 気象庁の配色と Hypsometric Tint を使う地図は、出典の表示が要る。
- 気象庁の配色は、暗い背景でコントラストが低い階級がある（80 mm/h 以上の紫は約 2.4:1）。
- 平年比の気象庁の配色は、中央がほぼ白。暗い背景では「平年並み」が最も明るく見える。

## 決定時点で未確認のこと

- 気象庁の配色の値は、指針の PDF（2020年7月版と読んだもの）と、降水ナウキャストの凡例の画像から書き写した。
  公開前に原典と照合し直す。
- 平年比の階級の境界は入れていない（資料ごとに違う）。
- ライセンスの条件は、採用時に配布元の記載を読んだ範囲のもの。GeoPalettes はリポジトリにライセンスのファイルがなく、
  README の記載（CC BY 4.0）に拠っている。
- turbo の作者の説明（順序のある量を正確に読ませる用途には向かない、という趣旨）は記憶によるもので、原典を確認していない。
- SAR の見本は、標高から作った模擬の画像だった。実際の SAR 画像で grayC を確認していない。
- 6分類以上のカテゴリ（土地被覆など、慣例の色があるもの）の扱いは決めていない。

## 見直すタイミング

- 明るい背景で viridis の黄緑が強すぎると感じる場面が増えた → 明るい背景用の連続の配色を別に選ぶ
  （候補: CARTO の系統、Crameri の batlow / lajolla）。
- 暗い背景で、RdYlBu の中央の明るさが読み取りを妨げた → 暗い背景だけ中央の階級を描かない
  （降水と同じ扱い）か、暗い背景用の発散の配色（berlin など）に分ける。
- 表にない種類のデータ（植生指数、夜間光、水深、土地被覆など）を扱うことになった → 対応表に行を足す。
- 気象庁が指針を改定した。
- turbo を既定にしたい場面が繰り返し出た → この ADR の A 案を、理由を添えて検討し直す。
