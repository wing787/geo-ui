# ADR 0003: 見た目の方向を「図葉」にし、UI を無彩色にする

- 状態: 採用
- 決定日: 2026-11-16
- 見直しの目安: 下の「見直すタイミング」のどれかに当たったとき

## 背景

v0.2.0 までの見た目は、暖かい紙白の背景、近黒の dark、ティールの差し色、等幅フォントの小さなラベル、
12px の角丸のカードという組み合わせだった。確認用ページを見て、全体に「AI が作ったように見える」という感想が出た。
どれも、生成されたページによく現れる既定の選択だった。主題（地図）から出てきた選択ではなかった。

見直しは、主題から形を決め直す方針で行った。確認用のモック（7種類のデータの見本、両テーマ）を作り、
それを見ながら決めた。モックはリポジトリに入れていない。

## 決定

1. **図葉として組む**。地図を図郭（インクの 1px の線）で囲み、経緯度の目盛を枠の外に出す。
   凡例・読み取り値・レイヤ・時刻の操作・縮尺・出典は、地図の上に浮かべず、図郭の外に置く。
2. **UI を無彩色にする**。背景・面・文字・枠・基図（海、陸、海岸線）はグレーだけ。
   **差し色（`--accent`）を廃止する**。色を持つのは、データと状態（エラー・警告・成功）だけ。
3. **強調と選択は、色ではなくインクで行う**。押されたボタンはインクの塗り。
   地図上の選択は、地の色の縁取り + インクの輪郭 + 図郭の目盛への表示。
4. **書体**は IBM Plex Sans と、整飾のデータ用に IBM Plex Sans Condensed（等幅数字）。
   IBM Plex Mono はコードだけに使う。IBM Plex Serif は使わない。
5. **面は直角**。角丸は操作部品にだけ 3px。ボーダーは両テーマとも 1px。
6. **文字サイズ**は 12 / 14 / 16 / 18 / 22。12px は図郭の目盛・縮尺・出典の3つだけに認め、それ以外は 14px 以上。
7. **デジタル庁デザインシステム（DADS）からルールを取り入れる**。見た目は借りない。

## 検討したこと

### 差し色

- ティール（v0.2.0 の dark の差し色）: viridis の中間の色とほぼ同じで、凡例の中に差し色が現れる。
- マゼンタ: データの色にない色相として検討した。色覚シミュレーション下で、データの色と十分に離れなかった。
- 差し色なし: 選択や強調に別の手段が要る。インクと縁取りで代替できることをモックで確認した。

差し色なしを選んだ。地図アプリでは画面の色のほとんどをデータが占めるので、UI の色はどれを選んでもデータと競合する。
衛星画像を表示したとき、枠と余白に色がないことが最も効いた。

### 凡例を地図の上に置くか、外に置くか

v0.2.0 は、地図の上に不透明な面を浮かべる前提だった（`--map-overlay-*`）。
外に置くと、地図が隠れず、文字のコントラストを下の地図に左右されずに保証できる。
狭い画面では整飾を地図の下に回す。やむを得ず浮かべる場合のために `--map-overlay-*` は残した。

### 最小の文字サイズ

DADS は 14px 未満を原則として認めない。図葉では目盛を 12px で組みたい。

- すべて 14px 以上: 基準に沿う。目盛の間隔が狭い箇所で重なりやすい。
- 12px を広く認める: 地図の注記としては普通の大きさ。読ませる情報まで小さくなる。
- **折衷（採用）**: 目盛・縮尺・出典の3つだけ 12px。凡例・読み取り値・操作部品は 14px 以上。
  目盛は地図の一部であり、凡例と読み取り値は読ませる情報だから。

### DADS の扱い

取り入れたもの: 文字のコントラストは大きさによらず 4.5:1、浮いた面は 3:1 の枠、フォーカスは2色の二重、
和文の字間 0.02em と斜体の不使用、色だけで区別しない、部品の操作とアクセシビリティの仕様の参照。

取り入れなかったもの: 色、書体（Noto Sans JP）、余白（8px 基準）、ウェイト（400 と 700）、角丸（8px から）。
そのまま借りると行政サイトに見える。DADS にはダークモードと、地図・凡例・チャートの部品の定義がない。

### Modern Web Guidance の扱い

Google Chrome の Modern Web Guidance（2026-11-10 時点）を、実装の作法の確認に使った。

取り入れたもの:

- `data-theme` を付けた要素で、地と文字の色を当て直す。`color` は確定した値で継承されるので、
  当て直さないと、light のページの中の dark の地図に light の文字色が残る。v0.2.0 の `base.css` にはこの抜けがあった。
- 文字サイズのトークンを px から rem にする。利用者がブラウザで設定した文字サイズに追従する。既定の設定では見た目は変わらない。
- 標準の部品を使い、`accent-color` をインクにする。
- 強制カラーモードで凡例の色見本を残す。押せる範囲を 44px 以上にする。

取り入れなかったもの:

- 「既定は OS の設定に従い（`color-scheme: light dark`）、手動の切替は設定画面に置く」という勧め。
  このリポジトリは、テーマをアプリの種類で決める（地図アプリは dark、読み物は light）。ADR 0002 の C 案を退けた理由と同じ。
- `light-dark()` に対応しないブラウザ向けのフォールバック。ADR 0002 の判断のまま。
  同ガイドは `light-dark()` を「Baseline Newly available（2024-05-13 から）」と書いている。

## この決定で生じること

- **破壊的変更（v0.3.0）**。廃止: `--accent`、`--accent-text`、`--font-serif`、`--text-xs`、`--text-md`、
  `--radius-sm` / `--radius-md` / `--radius-card`、`--border-hairline` / `--border-solid`、`--map-overlay-border-width`、
  色のプリミティブ（`--c-ink-*`、`--c-dk-*` のグレー、`--c-slate`、`--c-teal`）。
  変更: `--text-sm` は 13px から 14px（0.875rem）、文字サイズのトークンの単位は px から rem、`--border-width` は両テーマ 1px、`--focus-ring` はインク。
  追加: `--font-data`、`--text-map`、`--tracking-body`、`--radius-control`、`--focus-ring-halo`、`--map-*`。
- 下流のアプリは、地図を図葉として組むレイアウト（図郭、目盛、整飾）を実装する必要がある。
  共通の部品（凡例、目盛つきの枠）は、このリポジトリのコンポーネントとして用意するのが筋（未実装）。
- タイルの基図を使うアプリは、無彩色のスタイルを用意する必要がある。
- フォントに IBM Plex Sans Condensed が加わる。
- カテゴリ色の緑は、light の水域の上で 3:1 に届かない（2.7:1）。縁取りで補う前提にした。

## 決定時点で未確認のこと

- 実際の MapLibre の地図で、図郭の外に目盛を出す実装（地図の移動に追従させる）は試していない。モックは固定の範囲だった。
- カテゴリ色と、カラーユニバーサルデザイン推奨配色セットとの比較は行っていない。
- DADS の部品ごとの詳細ページと、Figma にある色の値は読んでいない。
- モックのチェックボックスは塗りだけで、チェックの印がない。コンポーネントを作るときに決める。

## 見直すタイミング

- 選択や強調が、インクと縁取りだけでは伝わらない場面が出た（例: 複数の選択を区別したい）。
- 目盛の 12px が読みにくいという指摘が出た。
- 狭い画面で整飾を地図の下に回すと、操作のたびにスクロールが要るなど、使い勝手に問題が出た。
- ポートフォリオの読み物のページで、無彩色だけでは単調すぎると判断した。
