# ADR 0002: テーマの切替に light-dark() を使う

- 状態: 採用
- 決定日: 2026-11-15
- 見直しの目安: 下の「見直すタイミング」のどれかに当たったとき

## 背景

当初の `tokens.css` は、light の値を `:root` に、dark の値を `[data-theme="dark"]` に、別々のブロックで書いていた。
この書き方には問題が2つあった。

1. `color-scheme` を宣言していなかったので、dark でもスクロールバーやフォーム部品が light の見た目のままだった。
2. トークンを足すときに片方のブロックに書き忘れても、何も警告されない。
   実際に、dark の `--border-strong` だけ生の hex が直書きされているなど、2つのブロックの食い違いが起きていた。

## 検討した選択肢

### A. 2ブロックのまま、`color-scheme` だけ足す

- どのブラウザでも動く。
- 書き忘れの問題は残る。

### B. `light-dark()` で1か所に書く

`--page: light-dark(var(--c-paper), var(--c-dk-bg));` のように、1つの宣言に両方の値を書く。
`[data-theme="dark"]` は `color-scheme: dark` を宣言するだけになる。

- 1つのトークンの light と dark が必ず並ぶので、片方だけ書き忘れることが構造的に起きない。
- 「地図コンテナだけ dark」「dark の中の一部だけ light」が、その要素の `color-scheme` を変えるだけで動く。
- 対応ブラウザが Chrome 123 / Firefox 120 / Safari 17.5 以降に限られる。
  非対応のブラウザでは色の宣言が無効になり、**配色がまるごと崩れる**（少し古く見える、では済まない）。
- 色以外（`--border-width`）には使えないので、そこだけは `[data-theme]` での上書きが残る。
- JavaScript から `getPropertyValue("--accent")` で読むと、解決前の `light-dark(...)` の文字列が返る。
  実値が要るときは、要素に当てた `color` の computed value を読む必要がある。

### C. `prefers-color-scheme` で OS の設定に従う

- 「ポートフォリオは light、地図アプリは dark」とアプリの種類でテーマを決める方針（DESIGN-SYSTEM.md §0）に合わない。

## 決定

**B を採用する。** 既定は `color-scheme: light`、`[data-theme="dark"]` で `dark`、`[data-theme="light"]` で `light` に戻す。

## 理由

- 書き忘れを構造的に防げる。このリポジトリは下流の全アプリに効くので、食い違いの影響が大きい。
- `light-dark()` は 2024年5月に主要ブラウザが出揃い、決定時点で約2年半が経っている。
- 想定する閲覧者（ポートフォリオを見る採用担当・エンジニア、地図アプリの利用者）は、更新されたブラウザを使っている見込みが高い。
- 下流のアプリがまだ無いので、切り替えの費用がかからない。

## この決定で生じること

- 上記より古いブラウザでは配色が崩れる。フォールバックは用意していない。
- 地図レイヤに UI の色を渡すときは、computed value を読む手順が要る（DESIGN-SYSTEM.md §1, §7）。
- `scripts/check-tokens.mjs` は `light-dark()` を自前で解釈している。入れ子の関数（`color-mix()` など）を
  セマンティック層で使い始めると、このスクリプトの拡張が要る。

## 見直すタイミング

- 古いブラウザ（特に iOS 17.4 以前の Safari）で崩れたという報告や、アクセス解析上の無視できない割合が出た。
- 組み込みの WebView など、ブラウザを選べない環境で使うアプリができた。
- JavaScript から色を読む場面が増え、computed value を読む手順が負担になった。

## A への戻し方

セマンティック層の各宣言を、`:root`（light の値）と `[data-theme="dark"]`（dark の値）の2ブロックに書き分ける。
トークン名は変わらないので、下流のアプリは変更不要。`color-scheme` の宣言は残す。
古いブラウザだけを救うなら、`light-dark()` の宣言の前に light の値だけの宣言を置く方法もある。
